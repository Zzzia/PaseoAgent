# PaseoAgent

基于 [Paseo](https://paseo.sh) 的个人助理 Agent 规范仓库。在这里启动的个人助理充当**用户与底层执行 Agent 之间的沟通与质量隔离层**——你只管用自然语言说清目标，任务派发、并行加速、方向纠偏、Prompt/文案把关和结果提炼，全部交给个人助理协调。

## 设计理念

- **不是角色扮演，也不是为了省 Token**：这个项目不是用来搞多角色圆桌讨论，也不是拿弱模型凑数省钱；我们的核心目标是**把市面上最强的模型组合起来扬长避短**——让自然语言与大上下文理解最强的模型管沟通、语义分析和文案把关，让代码与逻辑最强的模型管工程落地和硬核推理，同时对彼此独立的探索任务通过**多路并行加速**。
- **把强弱边界说透，没有万能模型**：
  - **`Linguist`**（默认首选）：强语言、强长上下文理解，适合日常调研、大文本/日志/评论语义分析、方案梳理和 Prompt 优化；**短板**是编程能力与复杂代码交付质量差。
  - **`Builder`**（工程主力）：强编程、逻辑严谨、执行快且交付靠谱，适合写代码、改需求、脚本、常规排障与运维；**短板**是自然语言表达与大文本理解弱，写文档和 Prompt 容易堆砌黑话、法条腔和防御性叠甲。
  - **`Grandmaster`**（终极攻坚）：深度推理与极难代码能力天花板，专啃复杂算法、硬核并发/系统排障和重度跨模块重构；**绝非万能**，语言与文本能力同样弱且成本更高，平时不轻易启用。
- **坦诚面对多 Agent 的代价并尽量降低损耗**：必须承认，多个 Agent 分工协作天然会带来**上下文隔离与信息传递折损**，如果拆分不当，最终交付质量反而可能不如单个强模型一竿子捅到底。因此本仓库的规则刻意围绕“减少上下文折损”来设计：
  1. **连续主线集中做**：同一批代码的连续迭代集中在一个主执行 Agent 里，由它统一收口正式改动，只对彼此独立的探索/验证任务并行；
  2. **轻量文本不硬外包**：Prompt、Skill、规则、文案这类助理自己上下文最清晰的活直接由助理完成，避免转手折损；
  3. **只同步目标，不微管理**：信任执行 Agent 的规划能力，向下交代清晰目标与关键红线，不替它编排琐碎步骤；
  4. **关键上下文落盘**：用本地 `.note/goal-<target>/` 持久化目标、已拍板决策与归属台账，避免长对话丢失重点。

## 快速开始（交给 AI 自动配置）

1. 克隆仓库并作为 Project 加入 Paseo：
   ```bash
   git clone https://github.com/Zzzia/PaseoAgent.git
   ```
2. 在本目录启动一个自然语言沟通能力强的模型作为个人助理，**先指定好你打算分配给 `Linguist`、`Builder`、`Grandmaster` 的三个模型**，直接把下面这句话发给 AI，让它阅读 [INSTALL.md](INSTALL.md) 自动帮你开启 Paseo Tools、确认 `paseo` / `paseo-help` 技能并配置好三类 Profile：

   > 请阅读 [INSTALL.md](INSTALL.md)，帮我完成本机的 Paseo 初始化配置（开启 Paseo Tools、确认 `paseo` 与 `paseo-help` 技能已启用，并配置三个执行 Profile）。我指定的三类模型如下：
   > - `Linguist`：<填你选的强语言/大上下文模型，例如 `antigravity/gemini-4-neon`>
   > - `Builder`：<填你选的强编程主力模型，例如 `opencode/openai/gpt-6.2-sol-fast`>
   > - `Grandmaster`：<填你选的深度推理旗舰模型，例如 `opencode/openai/gpt-6.2-astra-fast`>

3. 配置完成后即可直接对话使用：直接向个人助理提需求，或把 Paseo 里已有执行 Agent 的 `agentId` 发给它接管。多助理可同时运行，各自按 1 对 N 管控自己的执行 Agent，互不干扰，不污染 Paseo 标签。
